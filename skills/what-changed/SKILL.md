# Что изменилось на сервере

Используется, когда нужно объяснить изменение в файлах, сервисе или поведении.

## Порядок

1. **Что поменялось в файлах**
   Сначала git, потом mtime:
   - `git -C <репо> log --since='today' --oneline` — коммиты за день
   - `find <каталог> -newermt "today" -type f` — файлы, изменённые сегодня
   Сопоставить: если файл изменён, но в git его правки нет — правил кто-то
   вне git (рутина, другой агент, ручное вмешательство).

2. **События сервисов**
   `journalctl --since today --no-pager` — фильтровать по `Started`,
   `Stopping`, `Failed`. Показывает время перезапусков и падений.

3. **Кто запускал процессы**
   `ps -eo pid,lstart,cmd` — колонка `lstart` даёт время старта.
   Процесс, запущенный не в то время, что остальные, — главный подозреваемый.

4. **Логины**
   `last -n 20` и `grep <дата> /var/log/auth.log`. Отсутствие записей —
   тоже результат: чужого входа не было.

## Важно про интерпретацию

- **mtime не означает правку содержимого.** Сверять с `git diff`:
  если diff пуст, меняли только метаданные (touch, копирование).
- **Отсутствие записи в журнале не исключает существующее соединение** —
  переиспользованный SSH ControlMaster новой записи не даёт.
- Если причина не находится — так и сказать. Не додумывать.

## Что отчитывать

Хронологию с временем и источником каждого факта, в конце —
что осталось неизвестным. Разделять «доказано» и «предположение».
